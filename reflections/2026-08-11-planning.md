# Reflections — 2026-08-11 (planning phase)

Learnings captured during initial planning of the wind analyzer.

## Domain / data
- **Open-Meteo** is the right data source: free, no API key, hourly resolution, ERA5
  historical archive back decades, plus a companion geocoding API. Two endpoints:
  `archive-api.open-meteo.com/v1/archive` and `geocoding-api.open-meteo.com/v1/search`.
- `timezone=auto` is non-negotiable for this question — "calmest hour of day" only makes
  sense in *local, DST-aware* time. Requesting UTC would smear the pattern.
- Wind is reported at **10 m** height (ERA5 standard). Absolute values differ from
  sprinkler height, but the *hourly trend* (the thing we care about) holds.
- 5 years of hourly data is only ~44k rows — small enough for a single request and plain
  pandas in memory. No need for chunking or a database.

## Environment
- Local Python is **3.9.6**. Avoid 3.10+ syntax (`X | Y` unions at runtime) and `tomllib`
  (3.11+). Use `from __future__ import annotations` if annotations get fancy; keep config
  as a dataclass rather than TOML.

## Process
- The AskUserQuestion UI did **not** capture the user's free-text location — they picked
  the "I'll type it in Other" option but no value came through. Don't block on this:
  designing `location` as an editable config value (with a placeholder) + verifying with a
  sample city ("Boulder, Colorado") unblocks the whole build. Ask once, then proceed.
- Keep the structure small and flat for a "small project" — resist over-engineering.

## Conventions established
- `plans/` holds recorded plans (dated filenames).
- `reflections/` holds learnings per session/phase (dated filenames).
- Cache raw API pulls to `data/` (git-ignored) so re-runs are instant and API-friendly.
- CSV cache over parquet to avoid a pyarrow dependency.
